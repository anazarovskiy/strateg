# Анализ данных

Методики: `knowledge/data-analysis.md`; если метрика упала или выросла — `knowledge/diagnostics.md`.

1. Файл уже в реестре (`./strat source add`). Профиль: `./strat data profile <файл> --out projects/<проект>/analysis/profile_<имя>.md`. Разбери каждое замечание: смешанные единицы, пропущенные месяцы, выбросы, доли вперемешку с процентами.
2. Определения уточняй у руководителя, только если от них зависит вывод (например, кого считают «активным пользователем»).
3. Метод под вопрос: разложение метрики на составляющие (новые и старые пользователи, платформы, каналы, регионы), когортное удержание, «до/после» с учётом сезонности, проверка смены состава (парадокс Симпсона).
4. Расчёт — только скриптом `analysis/<имя>.py`: читает файл из `inputs/` или `sources/files/`, печатает результат и пишет `analysis/<имя>.md`. Запуск: `python3 projects/<проект>/analysis/<имя>.py`. Чисел «в уме» не бывает.
5. Результат зарегистрируй как источник: `./strat source add projects/<проект>/analysis/<имя>.md --kind analysis --reliability A --note "скрипт <имя>.py, вход S-…"`. Затем записи `--type estimate --method "…"` с цитатой из вывода.
6. В тексте: число, единица, период, с чем сравниваем, ссылка. Корреляция не доказывает причину: причина остаётся гипотезой до эксперимента.
