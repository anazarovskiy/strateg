# Приём задачи и маршрут

Задача руководителя: $ARGUMENTS

## 1. Проверь, нет ли уже проекта

Выполни `./strat status`. Если активный проект посвящён этой же задаче, это продолжение: работай по навыку `strateg-resume`. Если задача новая, иди дальше.

## 2. Выбери процесс

| Что в запросе | Процесс | Что будет |
|---|---|---|
| нужна стратегия, выбор направления, запуск или закрытие продукта | `full` | все этапы |
| узкий вопрос: «сколько», «кто конкуренты», «что разрешает закон» | `quick` | справка с источниками без вариантов |
| «что сказать аудитории», «почему не понимают ценность» | `comms` | акцент на барьерах и сообщении, продукт как ограничение |
| метрика упала или выросла, нужно понять почему | `diagnostic` | разбор метрики по `knowledge/diagnostics.md`, затем варианты |
| по готовому проекту пришли новые данные | `revisit` | навык `revisit` |
| бриф заказчика с заданной структурой сдачи, учебными числами и вопросом «вкладывать ли деньги» | `brief` | все этапы; вместо коммуникационной стратегии — модель и план по кварталам; итог в частях заказчика |

Сомневаешься между `quick` и `full` — начинай с `quick`, но переключайся, как только ответ упирается в выбор между вариантами.

## 3. Заведи проект

```
./strat init "<короткое название задачи>" --workflow <процесс>
./strat workflow <процесс> --why "<почему этот процесс>"
```

Создай в Claude Code список задач по этапам процесса, чтобы руководитель видел продвижение.

## 4. Веди этапы

Порядок для `brief`: `frame` (сразу `./strat deliverable set` по разделам брифа) → `collect` (бриф — источник S-001, все его числа — факты с цитатой) → `research` (открытые источники только для ориентиров, которых нет в брифе; без них расчёт строится на допущениях) → `options` → `product`, `model`, `validation`, `plan` → `report` (собрать `deliverable.md`) → `decide`.

Порядок для `full`: `frame` → `collect` → `research` (по необходимости `interview`, `data`, `ux`) → `options` → `product`, `comms`, `validation` → `report` → `decide` → `revisit` при новых данных. Для `quick`: короткий `frame` → `research` → `report`.

Человек нужен в четырёх точках (AskUserQuestion с вариантами, затем `./strat ask` и `./strat answer`):
- после постановки — подтвердить вопрос и рамку;
- перед дорогим исследованием — если оценка выше `budget_ask_threshold_usd` из `config/policy.json`;
- после вариантов — выбрать направление;
- перед фиксацией решения — ответственные, сроки, показатели.

Между этими точками работай сам и не отвлекай руководителя. Итог этапа сообщай одной-двумя строками и в том же ходе начинай следующий этап; не заканчивай ход вопросом «продолжать?». Если всё же так сделать, хук остановки вернёт работу.

## 5. Держи состояние в файлах

После каждого заметного шага выполняй `./strat next "<что дальше>"`. Перед долгим шагом — `./strat step <id> start`, после — `done` или `fail`. Тогда работу можно продолжить в любой момент, в том числе в другом чате.
