# Варианты

Методика: `knowledge/options.md`.

1. `./strat stage options start` — появится шаблон `options.md`.
2. Набросай 5–7 кандидатов, которые различаются по сути: аудитория, ценность, модель денег, канал, глубина (проверочный запуск или полноценный продукт). Оставь 3–5 самых непохожих. Статус-кво обязателен и описывается честно: у него тоже есть цена. «Закрыть направление» добавь, если оно не абсурдно; иначе оставь комментарий «закрытие не рассматриваем: …».
3. Для каждого варианта:
   - «Суть» — два-три предложения;
   - «Факты» — только `fact`, `observation`, `estimate` со ссылками;
   - «Что должно быть правдой» — гипотезы, каждая записью `hypothesis`;
   - «Прогноз» — эффект и затраты диапазоном, с допущениями (`assumption`);
   - «Затраты и риски».
4. Сильные возражения готовит субагент `critic`. Передай ему пути к `options.md` (без раздела «Рекомендация») и `research/findings.md`, больше ничего. Попроси по 2–4 самых сильных возражения на вариант и pre-mortem. Перенеси возражения в варианты без смягчения. Не согласен — ответь рядом аргументом со ссылкой, но не удаляй.
5. Сравнение по критериям из `brief.md`: ценность для аудитории, экономика, риски, обратимость, что нужно проверить. Где значение неизвестно, пиши «не знаем».
6. Рекомендация: какой вариант, почему, при каких условиях мы передумаем.
7. `./strat lint options.md`, затем `./strat stage options done`.
8. Выбор за руководителем: AskUserQuestion, рекомендованный вариант первым, `./strat ask` и `./strat answer`. Пока выбора нет, стратегию не пиши.
