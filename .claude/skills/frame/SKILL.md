# Постановка задачи

Цель — получить рамку, при которой понятно, какое решение мы готовим, и потратить на это не больше одного-двух обращений к руководителю. Методика: `knowledge/framing.md`.

1. `./strat stage frame start`.
2. Вытащи из запроса и приложенных материалов всё, что уже известно. Не спрашивай то, что видно в материалах.
3. Найди пробелы, без которых нельзя сделать следующий шаг. Обычно это:
   - какое решение принимается и кем;
   - для кого результат и к какому сроку;
   - жёсткие ограничения: бюджет, сроки, регулирование, что трогать нельзя;
   - какие данные есть у руководителя.
   Спроси через AskUserQuestion, не больше 3–4 вопросов за раз, с вариантами ответов. Каждый вопрос и ответ запиши: `./strat ask "…" --options "…|…"`, `./strat answer H-… "…"`.
4. Заполни `brief.md`. В разделе «Вопросы, которые могут изменить решение» перечисли 3–7 неопределённостей, ответ на которые поменяет выбор. Это вход для плана исследования.
5. Значимые утверждения руководителя занеси в реестр. Сохрани его формулировки как источник: запиши их в файл `sources/incoming/brief.txt` проекта и выполни `./strat source note --title "Бриф руководителя" --kind doc --verbatim --text-file <файл> --cleanup`. Затем записи: что он наблюдал — `observation`, что он думает — `hypothesis`.
6. Покажи руководителю рамку в 5–7 строках и спроси, верна ли она. Подтвердил — `./strat stage frame done`.

Плохой вопрос: «Расскажите подробнее о продукте». Хороший: «Что решаем по итогам: (а) запускать ли сервис, (б) на какой сегмент делать упор, (в) что менять в коммуникации?»
