# Решение и обязательства

1. `./strat stage decide start`.
2. У руководителя одним вопросом уточни: кто отвечает, к какой дате пересмотр, какие показатели считаем успехом. Предложи варианты на основе `strategy/validation.md`.
3. Запиши решение:
   ```
   ./strat decision add --title "…" --chosen "Вариант N" --basis C-…,C-… --owner "роль" \
     --metric "метрика ≥ X к дате|…" --review-by YYYY-MM-DD --review-if "условие 1|условие 2" \
     --rejected "Вариант M: причина|…"
   ```
   Основания — записи, на которых держится выбор, а не все подряд.
4. Обязательства из плана проверки и запуска: `./strat commit add --decision D-001 --who "роль" --what "…" --due YYYY-MM-DD`. Указывай роли, а не персональные данные, если руководитель не просит иначе.
5. Дополни `decisions/D-001.md`: почему отвергли другие варианты, что должно произойти, чтобы передумать.
6. `./strat stage decide done`, затем `./strat stage monitor start`.

## Сопровождение

- В начале каждой сессии смотри `./strat decision check` (хук включает его в сводку): просроченные обязательства, наступившие пересмотры, оспоренные или устаревшие основания.
- Выполненное обязательство: `./strat commit done K-… --note "…"`.
- Изменилось основание — переходи к навыку `revisit`. Если решение больше не опирается на запись, убери её: `./strat decision update D-… --remove-basis C-… --add-basis C-…`.
