# Финансовая модель

Методика: `knowledge/unit-economics.md`.

1. Все числа из брифа и материалов, которые войдут в расчёт, занеси фактами с цитатой: `./strat claim add --type fact --source S-001 --text "…" --quote "…"`. Учебные числа заказчика — тоже факты: их источник бриф.
2. `./strat model init`, затем заполни в `analysis/model.py`:
   - FACTS — ключ, значение, единица, формулировка, номер записи;
   - ASSUMPTIONS — базовое значение, низкое и высокое, единица, формулировка, что хуже (low/high), почему так, как проверить на малом запуске. Допущение без способа проверки — повод подумать, нужно ли оно;
   - compute() — расчёт с basis у каждого результата; MAIN — главный результат для чувствительности.
3. Обязательно посчитай: эффект к сценарию «без изменений», сверку «начало + новые − ушедшие», воронку по каналам без двойного счёта, вклад в прибыль (объём × цена × период), прямые расходы, границу решения (какое значение главного неизвестного даёт цель), предельные вложения или окупаемость по кварталам, базовый и слабый сценарии.
4. `python3 analysis/model.py` → `./strat model sync`. В документах ссылайся на номера записей, которые напечатал sync (`./strat model show`).
5. Покажи руководителю одной таблицей: главный результат в базовом и слабом сценарии и допущение, от которого он сильнее всего зависит. Спроси руководителя только о допущениях, которые он может знать сам (цена, бюджет, ставка), одним вопросом с вариантами.
6. Если допущение изменилось: правка в model.py, пересчёт, `./strat model sync`, затем `./strat impact` по изменившимся записям и правка затронутых разделов.
